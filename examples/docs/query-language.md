## House rules
- Rules are written in Sigma, never in raw Lucene. The Lucene query is generated by
  `sigma convert` (see DETECTION.md → Query).
- Use Sigma field names (`eventName`, `eventSource`). The pipeline maps them to ECS
  (`event.action`, `event.provider`). Check the mapping in the log-source doc when adding a field.
- Every rule needs `falsepositives`, plus at least one tactic and one technique tag.

## Bad forms
| Form | Symptom | Replacement |
|---|---|---|
| `eventName: stoplogging` | Zero results. Values are case-sensitive PascalCase | `eventName: StopLogging` |
| `sourceIPAddress|cidr: …` on AWS-internal calls | Misses them silently. Those calls have a hostname, not an IP | Filter on `aws.cloudtrail.user_identity.type` instead |
| Matching `requestParameters.name` as an object | Conversion fails or returns no matches. It's a flattened string | `requestParameters|contains: 'name=org-trail'` |
| Country as a full name (`United States`) | Zero results | ISO code: `US` |

## Platform limits
- Searches longer than 30 days time out on the CloudTrail index. Test longer windows in chunks.
- `es_query.sh` returns at most 10,000 events. The count is always exact, even above that.
